Two top-level sub-trees with distinct responsibilities:

- `scripts/` — Node.js + PowerShell toolchain orchestrated around `package.json` npm scripts. Core entry points: `build.ps1` (Windows NSIS + portable via electron-builder), `build-macos.sh` (macOS dmg/zip), `release-workflow.ps1` (interactive dev/build/post-update menu), and `publish-github-release.ps1` (packages `win-unpacked` into patch/full zips, uploads assets to a GitHub releases repo). Supporting helpers include `package-github-release.js`, `fetch-*-manifest.js`, `verify-update-package.js`, `electron-after-pack.js`, `ensure-electron.js`, `ensure-macos.js`, plus a large set of one-off data backfills (`backfill-*`, `import-*`, `seed-*`) and integration tests (`test-*.js`). The `web-installer/WebInstaller.cs` is a standalone WinForms C# program that downloads Setup.exe from GitHub; it is compiled by `build-web-installer.ps1` with token/version constants injected at build time.
- `supabase/migrations/` — timestamped SQL DDL files (e.g. `20260702_initial_hr_schema.sql`, `20260726_v178_leave_fraction_pause.sql`) consumed by `apply-pending-migrations.js`, which probes the live database schema via the Supabase JS client, decides which migrations are still needed, and executes them through either the Supabase Management API (`SUPABASE_ACCESS_TOKEN`) or direct Postgres (`SUPABASE_DB_PASSWORD`).

Dependency direction is one-way: scripts depend on `lib/supabase-client` and `package.json`; they never import application source code. Legacy Google Sheets glue lives under `scripts/legacy/lib/` and is kept separate from current Supabase flows.
