- `app.js` is the single entry: it creates an Express instance, installs `cookie-parser`, `express-session`, JSON body parsing, static file serving for `public/`, a global error handler, and `/login` + `/` SPA redirects.
- All business routes are mounted as sub-routers under `/api` via `routes/api.js`, which itself mounts domain routers (`/admin/users`, `/bonus-requests`, `/sales`, `/expenses`, `/loan-requests`, `/hrms`, etc.) — so every child route lives behind one mount point.
- Authentication is centralized in `routes/api.js`: `requireAuth` resolves the session from `x-session-id` or `req.session.appSessionId`, validates it against `../lib/session-store`, enriches `req.userRole` through `roles.enrichUserRole`, and attaches `realUsername`/`impersonatingAs`/`username`/`userRole` onto the request. Child route files never implement their own auth; they rely on these enriched fields.
- RBAC overrides and sales-action permissions are preloaded at startup by requiring `./lib/role-permissions`, `./lib/user-permissions`, and `./lib/sales-action-permissions` before any request is handled, so all children share the same effective permission matrix.
- A separate `/api/supabase` router (`routes/supabase`) is mounted directly from `app.js` outside the main `apiRoutes` tree, giving Supabase-specific endpoints bypassing the shared auth/RBAC stack.
- Cross-cutting helpers defined in `routes/api.js` (`parseCompany`, `filterEmployeesForRequest`, `assertEmployeeInCompanyContext`, `sessionFromRequest`) are reused by multiple child routers to enforce company-scoped employee visibility uniformly.
