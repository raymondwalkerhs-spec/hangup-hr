Two independent Electron entry points share the same pattern: an Express server is started on localhost (main.js → port 3847, backup-main.js → port 3848), then a single `BrowserWindow` loads the login page from `http://127.0.0.1:<PORT>/login`. The main process owns Node-only APIs — file dialogs (`pick-folder`, `write-file-buffer`), session lifecycle (`set-session`/`clear-session`), uninstall trigger, and GitHub-based self-updater (`check-github-update`, `apply-github-update`, `relaunch-app`) — and exposes them through `contextBridge.exposeInMainWorld('hrDesktop', ...)` in `preload.js` / `backup-preload.js`. The renderer runs a vanilla JS SPA served from `public/`: `index.html` defines the shell (sidebar nav, sync overlay, modal root) and pulls feature scripts (`app.js`, `sales.js`, `expenses.js`, `team-dashboard.js`, …) while `login.html` handles sign-in; all client HTTP calls go to `/api*` against the local Express app created by `../app` (or `../backup-app`). A 5-minute polling loop in main checks Supabase auth to enforce admin revocation or forced uninstall. `public/js/app.js` is the SPA core (state object, `api()` fetch wrapper with `x-session-id`, silent refresh, permission helpers like `canViewReports`, `canEditAttendance`, etc.) and each feature module registers itself against it. The backup app mirrors this structure with its own preload and `public/backup/` pages, using a separate single-instance lock role (`hangup-backup`).
