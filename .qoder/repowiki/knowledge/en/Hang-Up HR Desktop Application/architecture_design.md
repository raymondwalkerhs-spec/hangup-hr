The repo is a single Node/Electron monorepo whose `main` entry (`electron/main.js`) starts two processes: the Electron browser shell hosting the SPA and a parallel Express server (the `express_server` child) mounted under `/api`. The server loads per-domain route modules that call into the `business_logic` layer, which in turn persists through a Supabase client. A second Electron process (`electron/backup-main.js`, launched via `npm run backup`) runs the standalone backup app. Cross-cutting concerns — packaging via electron-builder, NSIS/Dist targets, GitHub releases, Supabase migrations, Airtable backfills, and test orchestration — live in `scripts/` and are invoked from the root `package.json` scripts, so every child module is wired together by this top-level manifest rather than by inter-package imports.
