Three cooperating leaf modules with a clear dependency direction:
- `sales-scope.js` owns row-level visibility (`defaultCanViewSale`, `filterSalesForUser`) and approval gating; it depends on `./roles` for rank/lead-team helpers and delegates the `approve_sale` action check to `sales-action-permissions`. It also provides dashboard helpers (`buildSalesDashboard`, `countSaleForDashboard`).
- `sales-action-permissions.js` is a small in-memory-cached layer over the `sales_action_permissions` Supabase table. It exposes `canPerformAction`/`canPerformActionSync`, `upsertActionPermission`, `seedDefaults`, and an `invalidateCache` hook; when Supabase is unavailable it falls back to the in-process `DEFAULT_ACTIONS`.
- `sales-access-resolver.js` is the single source of truth for field + attachment access by surface (`main`, `quality`, `edit`). It imports the static catalog from `./sales-field-catalog` and resolves roles via `rolesForSurface`, which reads snake_case or camelCase columns (`view_roles`/`viewRoles`, `edit_roles`/`editRoles`, `main_view_roles`/`mainViewRoles`, `quality_view_roles`/`qualityViewRoles`) so callers can pass either DB rows or repo-normalized objects. Special-case logic exists for `verifierFeedback` / `clientFeedback` and quality-only fields (`QUALITY_ALWAYS_HIDDEN`, `QUALITY_EXTRA_FIELDS`, `SUBMIT_EXCLUDED_KEYS`).

No internal sub-packages — each file is a flat CommonJS module exporting pure functions plus constants, making them easy to test and reuse across controllers/services.
