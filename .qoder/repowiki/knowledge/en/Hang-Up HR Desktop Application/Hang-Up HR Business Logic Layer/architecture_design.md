All domain modules in lib/ are pure service layers that depend on a single data-abstraction entry point: `lib/backend.js` resolves the active backend via `DATA_BACKEND` env var and returns `./supabase-repo`, which every business module imports for CRUD/query access. Cross-cutting concerns are factored into shared helpers consumed by multiple domains — `auth-supabase.js` supplies session/company context, `cache.js` provides an in-memory LRU cache, `data-store.js` wraps SQLite persistence, `storage.js` abstracts Dropbox/Supabase Storage, and `notifications.js` / `notify-*` modules deliver alerts. Domain boundaries are enforced by file-per-domain convention (e.g. `payroll.js` + `payslip-*.js`, `sales-*.js`, `attendance-*.js`) with no cross-import between sibling domains; inter-domain flows (e.g. attendance → payroll, sales → Airtable sync) go through the repo layer or event-driven notification dispatch rather than direct calls. Startup wiring is centralized in `app-bootstrap.js` (`loadEnvironment`, `ensureCacheDirectory`, `assertSupabaseConfigured`) before any domain module is required.
