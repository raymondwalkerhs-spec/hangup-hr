Flat `lib/` module set split by responsibility rather than layered:
- `hrms-repo.js` is the persistence facade over Supabase (`getSupabaseAdmin()`), exposing CRUD for `employment_periods`, `org_teams`/`team_tls`, `action_improvement_plans`, `onboarding_checklists`, `offboarding_checklists`, `clearance_items`, `equipment`/`equipment_assignments`, `leave_requests`, `public_holidays`, `payroll_month_locks`, and `app_sessions`. It also builds live org structures from `data-store` + `id-generator` and reassigns dialing-agent IDs via `UNIT_ID_RULES` when teams move units.
- `employee-identity.js` owns the stable internal_id vs changeable app_id boundary: a single `EMPLOYEE_ID_COLUMNS` registry drives `reassignAppIdReferences` / `syncAllInternalIdsForAppId`, while `migrateEmployeeAppId` and `releaseEmployeeAppId` perform FK cascade updates and placeholder-ID generation (`DEL-${short}`).
- `employee-ids.js` handles ID-space utilities (reserved-id collection, former-id parsing, leadership-prefix sorting, promotion-era resolution via `promoted_from_id`/`promoted_to_id`/`effective_from_month`).
- `employment-periods.js` is pure date-math (ISO parse, month-in-range, Monday/Friday helpers) consumed by payroll/export logic.
- `employee-compliance.js` normalizes nationality/permit/insurance fields with Egyptian-nationality branching; `employee-status.js` centralizes status keys, display labels, and payroll-eligibility predicates; `hr-constants.js` holds enum-like option lists (teams, payment methods).
- `employee-privacy.js` strips sensitive fields based on `roles.canView*` checks before API responses.
- `employee-export.js` composes attendance summaries into CSV/PDF using `pdfkit` and delegates identity resolution to `employee-ids`.
Dependency direction is one-way: business helpers (`employee-*`) depend on `hrms-repo` only where they need DB access; `hrms-repo` depends on `data-store`, `id-generator`, `roles`, `company-context`, and `team-names`; no circular imports among the leaf files.
