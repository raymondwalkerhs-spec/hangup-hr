Five sibling modules form a thin update-and-audit layer above the Electron runtime:
- `app-version.js` is the shared versioning primitive — parses semver-like strings (with pre-release tokens) and exposes `compareVersions`, `isVersionLessThan`, and `evaluateVersionCompatibility` against a policy object.
- `version-sheet.js` fetches the canonical policy from Supabase (`app_versions` table) via `getSupabaseAdmin()` and normalizes it into `{currentVersion, minCompatibleVersion, forceUpdateMinVersion, releaseType}` plus user-facing messages; `fetchVersionPolicy` wraps it with a try/catch that returns null on failure.
- `github-updater.js` is the primary updater: detects install kind (nsis/mac/portable) from `process.execPath`/env, queries `https://api.github.com/repos/<repo>/releases/latest`, picks a platform-matching asset by regex, downloads it, extracts via `zip-extract`, validates the payload ASAR header through `update-integrity`, then stages the new bundle in `tmpdir` and writes an atomic-swap manifest (`hangup-hr-atomic-swap.json`) containing `{stagedPath, targetPath, backupPath, exe, version}`. On next launch `recoverOrCompleteUpdate` reads the manifest, spawns a platform-specific `.bat`/`.sh` script to move the staged tree over the live install and relaunch, and also checks install health by re-validating the running `app.asar`.
- `update-integrity.js` provides low-level helpers: `validateAsarHeader` reads the first 8 bytes + JSON header to confirm an ASAR file, `sha256File` computes SHA-256, and `copyFileVerified` copies through a `.hr-staging` temp file for double-check before committing.
- `changelog.js` is a separate concern — all entity mutations funnel through `logChange` which inserts into the `change_log` Supabase table via `getSupabaseAdmin()`, with convenience wrappers per entity (employee, attendance, bonus, deduction, config, warning, month_profile). It has no dependency on the updater.

Dependency direction is one-way: `github-updater.js` → `app-version.js`, `update-integrity.js`; both `version-sheet.js` and `changelog.js` depend only on `supabase-client`. No module imports another sibling except through these two primitives, keeping the updater self-contained and the changelog independently usable.
