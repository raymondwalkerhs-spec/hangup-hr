Four sibling modules with no internal sub-packages, each exporting a small focused API:
- `documents.js` is the storage facade: it owns the allowed `DOC_TYPES`, image MIME guessing, and thin wrappers around `./storage` (`uploadFile`, `getStorageFileStream`, `deleteStorageFile`) plus helpers `uploadProfilePhoto` / `uploadEmployeeFile` that normalize return shapes.
- `pdf-export.js` is stateless — pure functions driven by `pdfkit` that accept data + month and return a `Buffer`. A shared `pdfBuffer(buildFn)` helper creates an A4 doc, collects chunks on `data`, resolves to `Buffer.concat(chunks)` on `end`, and rejects on `error`; three builders (`buildPayrollTablePdf`, `buildMonthlyReportPdf`, `buildPaymentSheetPdf`) compose reusable `section`/`row` helpers and handle page breaks at `y > 720–740`.
- `export-zip.js` orchestrates cross-module reads from `../lib/data-store`, `../lib/payroll`, `../lib/attendance`, `../lib/payslip-pdf`, `../lib/changelog`, and `../lib/roles` to build two archives via `archiver`: `buildFinanceHandoffZip` (CSV payroll + CSV changelog + per-employee payslip PDFs) and `buildDocumentsZip` (streams stored files through `documents.getDriveFileStream`). Both use the same chunk-collecting `Promise` pattern as `pdfBuffer`.
- `zip-extract.js` is a standalone Windows-safe zip extractor using `adm-zip` with manual entry iteration, path normalization, empty-entry rejection, and optional `.asar` header validation via `./update-integrity`.
Dependency direction is one-way outward: this module depends on `data-store`, `payroll`, `attendance`, `payslip-pdf`, `changelog`, `roles`, `storage`, and `update-integrity`; nothing inside the scope imports each other except `export-zip.js` → `documents.js`.
