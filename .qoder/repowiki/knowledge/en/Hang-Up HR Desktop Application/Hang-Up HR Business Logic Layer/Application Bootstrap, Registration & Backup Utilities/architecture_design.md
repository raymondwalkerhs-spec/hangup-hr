This leaf module is a collection of small, single-responsibility utilities that are required early by other layers rather than being organized into sub-packages.

- Startup / bootstrap: `app-bootstrap.js` probes multiple locations for `.env` (process.env.HR_APP_ROOT, __dirname, cwd, Electron resourcesPath, PORTABLE_EXECUTABLE_DIR, execDir) via dotenv, creates HR_CACHE_DIR, and asserts Supabase configuration. `backend.js` is the sole DATA_BACKEND switch — it forces `supabase`, rejects `sheets`, and lazily requires `./supabase-repo` through `getBackend()`.
- Agent registration: `registration.js` implements the daily 4-digit PIN + pending-approval flow against the `agent_registration_requests` and `registration_daily_pins` tables via `./supabase-client`, then coordinates with `./data-store` to create employees and `./users-admin` to provision app users; role sets (`PIN_VIEW_ROLES`, `APPROVE_ROLES`) and an owner auto-activate list come from env.
- Backups: `backup-service.js` orchestrates full and sales-only backups by paging rows from every table in `BACKUP_TABLES` (`backup-tables.js`) plus attachments from `sales_attachments`, downloading files from the configured storage bucket, and writing a `manifest.json`; `backup-jobs.js` provides an in-process Map-backed job tracker (`createJob`/`updateJob`/`completeJob`/`failJob`/`pruneOldJobs`) used to surface progress back to callers.
- Platform helpers: `uninstall.js` spawns the bundled Windows uninstaller silently; `egypt-datetime.js` formats dates in Africa/Cairo via Intl.DateTimeFormat; `calendar.js` computes working days per month; `us-states.js` exports the US state list for sale addresses.

Dependency direction is one-way outward: this module imports from `supabase-client`, `storage`, `business-repo`, `data-store`, `sales-export`, `notify-routing`, and `users-admin`, but no other module imports these files except as entry points or shared constants.
