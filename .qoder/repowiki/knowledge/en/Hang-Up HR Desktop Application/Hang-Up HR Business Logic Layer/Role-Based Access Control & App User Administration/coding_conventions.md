- Every business capability exposes a `canXxx(userRole)` function that delegates to `perm("featureKey", userRole, () => legacyDefaultFn)` so the effective decision always flows through the override pipeline before falling back to a hardcoded role list.
- Override persistence modules share an identical shape: a module-level `{ loadedAt, overrides: Map }` cache with a 60s TTL, a `loadOverrides(force)` that deduplicates concurrent requests via a shared `loadPromise`, and an `invalidateCache()` that resets both fields.
- Role names are normalized once via `normalizeRole(role)` (lowercased, trimmed, alias-mapped, defaulted to `none`) and used consistently across all files instead of raw strings.
- Feature keys in the catalog are snake_case identifiers paired with human-readable `label`, `category`, and `description` entries, and every write path filters payloads through `catalog.getPermission(key)` to reject unknown permissions.
- Database errors indicating missing columns or relations (e.g. `is_it` column not yet migrated, `app_role_permissions` table not yet created) are caught and treated as "empty result" rather than fatal, allowing the app to run during schema rollout.
