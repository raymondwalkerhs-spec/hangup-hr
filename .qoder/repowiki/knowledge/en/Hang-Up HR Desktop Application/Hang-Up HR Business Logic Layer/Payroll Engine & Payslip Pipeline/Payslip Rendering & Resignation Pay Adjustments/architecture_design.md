Three focused leaf modules with a one-way dependency chain: `payslip-detail.js` is the pure data layer — it builds structured line items (`bonusLines`, `deductionLines`, `attendanceLines`) from raw payslip/attendance/bonus/deduction records using helpers like `formatLongDate`, `monthPayrollFolderName`, and `employeeDisplayName` from `./attendance`; `payslip-pdf.js` depends only on `buildPayslipPdfContext` from that module and drives a `pdfkit` document stream (A4, 50px margin) to render sections (Salary basis, Attendance notes, Bonuses, Deductions, Balance due) into a Buffer; `resignation-payroll.js` is independent of the PDF path and instead composes `./month-profile.lookupSalary`, `./departure-deductions.createNoNoticeDeductions`, and `./attendance.summarizeEmployeeMonth` through a `store` interface (`getPayrollAdjustment`, `getPositionRates`, `getConfig`, `getWorkingDaysForMonth`, `getAttendanceEvents`, `upsertPayrollAdjustment`) to compute a tiered notice-period pay scale (`NOTICE_PAY_SCALE`) based on passed sales thresholds and persist adjustments. There is no shared state between the three files — they are invoked by higher-level payroll orchestration code.
