Three cooperating modules form the payroll engine:
- `payroll.js` is the entry point exporting `buildPayroll`, `calcPayrollRow`, and `buildEmployeePayrollHistory`. `calcPayrollRow` resolves an employee's position/salary via `month-profile`, computes daily rate from working days (`attendance`), adds transport allowance (`transport`), tiered commission (`commission-tiers`), loan installments (`loans`), and Action Improvement Plan penalties/notes (`action-plans`), then returns a flat payslip row. `buildPayroll` groups bonus/deduction/adjustment events by employee, filters eligibility via `isPayrollEligibleForMonth`, and delegates final net adjustments to `payroll-splits.applyPayrollSplits`.
- `payroll-splits.js` owns the split lifecycle: constants (`SPLIT_KINDS`, `SPLIT_STATUSES`), id generation, month arithmetic (`shiftMonth`), map building (`buildSplitMaps`), validation (`validateSplit`, `buildValidationContext`), and the core formula that turns a calculated net into gross payable / received / deferred / pending / correction totals plus remaining balance. `applyPayrollSplits` mutates the payslip row in place.
- `payroll-schedule.js` derives cash-out views from accrual data: agent payments are due on the 15th of the following month, training payouts follow program milestones; `buildTotalPaidView` merges prior-month accruals with received splits to produce a per-calendar-month summary.

Dependency direction is one-way: `payroll.js` → `payroll-splits.js` → `payroll-schedule.js`; each file only imports sibling helpers or external domain modules (`attendance`, `month-profile`, `transport`, `commission-tiers`, `loans`, `action-plans`, `hr-constants`). There is no shared state — all inputs are passed explicitly and outputs are plain objects.
