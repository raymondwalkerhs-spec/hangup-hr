Three cooperating files form a layered leaf module with clear dependency direction:
- `lib/training-pay-rules.js` is the pure-function core: constants (`PROGRAM_OUTCOMES`, `MIN_SALES_PER_PHASE`, `TRAINING_DAILY_RATE`, etc.), date helpers, attendance-to-unit conversion, phase-sales evaluation, and the single-source-of-truth predicates (`isTrainingPayDate`, `computeEligibleTrainingPayDates`, `computeProgramTrainingPayDatesBeforePromotion`, `hasDualPayrollInMonth`, `resolveTrainingPayrollAnchorMonth`). It depends only on `./calendar` and `./payroll-splits`.
- `lib/training-phases.js` is the Supabase-backed persistence layer. It owns CRUD over `agent_training_programs` / `agent_training_phases` tables, enforces status/exit-reason enums via `PHASE_STATUSES`/`PHASE_EXIT_REASONS`, builds 4-week Mon–Fri phase schedules (`buildPhaseWeeks`), counts per-phase sales through `business.readSales`, and exposes high-level ops (`createProgram`, `updatePhase`, `promoteToAgent`, `loadProgramsForEmployees`). It re-exports the rule functions from `training-pay-rules` so callers get both persistence and business logic in one facade.
- `lib/training-payroll.js` is the payroll integration layer. It takes an existing standard payroll row (from `./payroll.calcPayrollRow`) and enriches it by detecting training programs (`programsByEmployee`), computing eligible training vs agent date sets, building a `dual` row that nests `training` + `agent` sub-rows, deferring to non-anchor months as `training_deferred_month`, and applying payroll splits filtered by kind (`applySplitsToKind` → `splitMatchesKind`). It also provides tab-flattening helpers (`flattenForTrainingTab`, `flattenForAgentTab`) and totals aggregation.

Dependency direction: `training-phases.js` → `training-pay-rules.js`; `training-payroll.js` → `training-pay-rules.js` + `./payroll` + `./payroll-splits` + `./attendance`. No cross-import between phases and payroll beyond the shared rules file.
